## 1. Jev とは

TypeSafe AI が 2026-09-15 に公開した「System One モデル」の第 1 弾。
LLM とは根本的に違い、**文章を一切生成せず、型付きの判断と確率だけを返す**。

| 項目 | 内容 |
|---|---|
| エンドポイント | `POST https://api.typesafe.ai/v1/systemone` |
| モデル ID | `jev-latest`（エイリアス）/ `jev-1.13`（ピン留め） |
| リクエスト | `state`（判断材料）+ `questions`（質問マップ） |
| 入力形式 | テキスト / JSON / テキスト配列。**画像・音声・動画は未対応** |
| コンテキスト | 32K トークン |
| 料金 | 入力 **$0.042 / 1M tok**、**出力は無料**、キャッシュ入力 $0.00 |
| レイテンシ | 70〜500ms（公称） |
| 提供形態 | ホスト型のみ。**重み非公開・on-prem 提供なし・ファインチューン不可** |
| ステート | 完全にステートレス。呼び出し間で学習しない |
| SDK | `typesafe-sdk`(Python) / `@typesafe-ai/sdk`(JS)。OpenRouter / Vercel / Cloudflare / LiteLLM / LangChain 経由も可 |

### 3 つの質問プリミティブ

| 型 | 用途 | 戻り値 |
|---|---|---|
| `choice` | 最大 255 択から 1 つ選ぶ | `choice`, `probabilities`, `confidence` |
| `score` | 2〜10 段階の順序ルーブリックで採点 | `score`（連続値）, `legend`, `probabilities`, `confidence` |
| `noul` | 命題が真である確率 | `noul`（0〜1）。**confidence フィールドは無い** |

**TypeSafe 自身が公開している失敗モード（9 項目）のうち、金融用途に効くもの:**

- **計算が苦手** → 指標計算は必ずコード側
- **日付比較が苦手** → 保有期間・受渡日の判定はコード側
- **1 質問内でのカウントが不安定** → 「1 項目 = 1 noul」にしてコード側で合計
- **スキーマ外の値は返らないが、スキーマ内の間違った値は返る**（「ハルシネーションゼロ」は型の話のみ）
- **`choice`（相対）と `noul`（絶対）の数値は比較できない** → しきい値を混ぜるな、と TypeSafe が明示的に警告
- **state は「データ」として扱われ「敵対的入力」として扱われない** → 注入や誤誘導で判断が動く
- **数値表現より意味表現に強い** → ★これは設計に直接響く（§5 参照）

### トークンはどこから出るのか — 3 つの別勘定

### 1 リクエストの内訳（1 銘柄 × 1 時点。3 戦略 8 質問すべてを含む）

| 要素 | トークン |
|---|---|

| `questions` | **1,776** ← 毎回同じ内容。ここが 88% を占める |
| envelope | 15 |

| **単価** | **0.0128 円 / リクエスト** |

> これが questions ブロックに効くなら費用は実質ゼロに崩れる。

## 3. リアルタイム化 — 個人 PC 購入 vs API 利用

### まず前提を正す

**Jev は重みが非公開で on-prem 提供がない。** つまり PC を買っても Jev は動かない。
「ローカル案」は実質「**別の公開重みモデルで Jev を代替する**」という別の話になる。

### それでも金額を計算すると

**ローカル PC の固定費**（GPU 32GB 級の自作機一式 70 万円、3 年償却、500W）

| 項目 | 市場時間のみ稼働 | 24 時間稼働 |
|---|---:|---:|
| 本体償却 | 19,444 円/月 | 19,444 円/月 |
| 電気代（31 円/kWh） | 2,116 円/月 | 11,160 円/月 |
| **月額合計** | **21,560 円** | **30,604 円** |

**損益分岐リクエスト数**

| 稼働形態 | 分岐点 | 日足運用との比 | 5 分足・全銘柄との比 |
|---|---:|---:|---:|
| 市場時間のみ | 月 **1,688,334** req | 分岐点の 1/20,099 | 分岐点の **1/258** |
| 24 時間 | 月 **2,396,570** req | 分岐点の 1/28,531 | 分岐点の 1/366 |

**5 分足で全銘柄を全力で回しても、分岐点の 1/258 にしか届かない。** 桁が 2 つ以上足りない。

### レイテンシで見ても PC は無意味

| 経路 | レイテンシ |
|---|---|
| Jev API | 70〜500ms（公称）+ 日本-US 往復 100〜150ms ≒ **200〜650ms** |
| ローカル小型モデル | 50〜200ms 程度 |

差は数百 ms。**しかし株価データ側が yfinance で 15 分遅延**なので、
PC を買っても「リアルタイム性」は 1ms も改善しない。

### 判定

> **API 利用が正解。PC 購入は推奨しない。**
>
> 理由は 3 つ:
> 1. Jev は自己ホストできないので、PC を買っても目的の判断エンジンが動かない
> 2. コストで見て桁が 2 つ以上合わない
> 3. リアルタイム性のボトルネックは**モデルではなく株価データ**
>
> **本当にリアルタイム性が必要になったら、GPU ではなく証券会社のリアルタイム
> データ API に投資するのが正しい。**（例: 立花証券 e 支店 API — 口座開設無料で
> リアルタイム株価・板情報・20 年分の日足、Python 対応、デモ環境あり）

### 4.2 検証結果 — ここが最重要

| 検証 | 結果 | 解釈 |
|---|---|---|
| **TradeRank Season 9**（競技ベンチマーク） | Jev は 16 の LLM 勢に混じった**唯一の非 LLM 参加者**。ライブルール再現で 22 エントリー（21 ショート）、**−2.58%**、清算なし。同期間 BTC −20.33% / SPY +5.49%。勝率 0.4907、**Brier 0.3084**。**142 日バックテストではエッジなし** | 下落相場でショートに寄せて −2.58% は「大負けしていない」が、勝率はほぼコイン投げ。**Brier 0.3084 は「常に 0.5 と答える予測器（0.25）より悪い**」 |
| **Kalshi 予測市場ボット** | 再現可能なブラインドバックテストで **Brier 0.209 vs 市場の板 0.157**（n=601） | 板より明確に劣る。**ブラインドの Jev にエッジなし** |
| **michaelpersonal/jev-trade-cc** | 2022-01-03〜2026-09-18、$100k long-only → **$171,060** vs 指数 $159,500、より浅い DD。113 クローズ、勝率 32.7%、profit factor 1.5 | **著者自身が「指数超過分は MRVL 1 銘柄（+125.9%）に大きく依存」と明記**。単一ポジション依存は再現性が疑わしい |

**Brier score の読み方（重要）**

- 常に 0.5 と答えるだけの予測器 → **Brier = 0.25**
- TradeRank の Jev → **0.3084**（＝それより**悪い**）
- Kalshi の Jev 0.209 vs 市場板 0.157 → 0.25 は切ったが**板に負けている**

→ **公開されている厳密な検証では、Jev に単独のアルファは確認されていない。**
Jev の訴求点は**レイテンシ・型付き出力・コスト**であって、予測精度ではない。

### 4.5 検証面の注意点（複数ソースが共通して指摘）

- **ベンチマークは TypeSafe 自社製。** 独立した第三者による再現はまだ。
  DOOM の自動プレイや Wikipedia リンク競走といった自社設計ワークフローから算出された数字で、
  TypeSafe 自身が「評価の作り手による偏りの可能性」を注記している
- 参照解答が**他の 2 モデルの平均**から作られている
- TypeSafe は**価格が補助されていないことを示せないと認めており**、
  報告された数値は典型値ではなく best case と想定すべきと述べている

## 5. 先行事例から得た、本実装への反映

### 5.1 既に設計と一致していたもの

| 先行事例の知見 | 本実装での扱い |
|---|---|
| **"Jev judges, code executes"**（全プロジェクト共通） | 指標計算・約定・サイズ・損切り・現金下限はすべて Python 側。`strategies.yaml` の Jev は判断のみ |
| **state を匿名化**（ティッカー無し・日付無し・絶対価格無し）。「2026 年カットオフのモデルは検証期間に何が起きたか知っている」ため | `anonymize: true` で既定 ON。`state_schema.py` が銘柄名・実日付・絶対価格を構造的に排除 |
| **`choice`（相対）と `noul`（絶対）のしきい値を混ぜない** | `strategies.yaml` で質問ごとに独立して定義。`routing` のしきい値も型別に分離 |
| **選択肢には説明文を付ける**（ラベルのみだと confidence 0.82 → 0.60 に低下） | 全 `criteria` に日本語の定義文を記述済み |
| `choice` は必ず「勝者」を作るので「該当なし」は独立した `noul` で聞く | `trend_intact` / `not_falling_knife` を独立 noul として分離 |

### 5.2 設計を修正すべきもの ★

**「Jev は数値表現より意味表現に強い」** — 一部のプロジェクトは
**float を一切 Jev に渡さない**方針を取っている。

現状の私の `state_schema.py` は 16 個の観測値すべてが float。
これは先行事例の知見に照らすと**弱点**。

**対応: state を 2 モードで作れるようにし、どちらが効くか自分のデータで比較する。**

| モード | 例 |
|---|---|
| `numeric`（現状） | `"price_vs_sma50_pct": 2.4` |
| `semantic`（追加） | `"price_vs_sma50": "やや上"`, `"rsi14_band": "中立(40-60)"` |

どちらが優れているかは推測ではなく **§5.3 の検証で決める**。

### 5.3 検証を最優先の成果物にする ★★

先行事例が示したのは「Jev の予測精度は自明でない」ということ。
したがって**このシステムの第一の成果物は PnL ではなく、Jev の判断が信用できるかの測定**。

**撤退ラインを事前に決めておく:**

1. **キャリブレーション**: `noul` が 0.7 と言ったとき、実際に 70% 起きるか。
   Brier score を測り、**0.25（常に 0.5 と答える予測器）を切れなければ判断エンジンとして失格**
2. **ベースライン超過**: バックテストは必ず以下と並走させる
   - buy & hold
   - 単純なルールベース（SMA ゴールデンクロス等、Jev を使わない）
   - ランダム売買
   **ルールベースに勝てないなら、Jev を挟む意味がない**
3. **単一銘柄依存チェック**: 超過リターンを銘柄別に分解し、
   1 銘柄を抜いたら優位が消えるなら結果を信用しない（jev-trade-cc の失敗パターン）
4. **匿名化 ON/OFF の差分**: 匿名化を外して成績が跳ね上がるなら、
   それは**予測力ではなく学習データリーク**の証拠

## 6. 総合判断と推奨

### 作るべきか

**作るべき。ただし目的の設定を変える。**

| 目的設定 | 評価 |
|---|---|
| ❌「Jev で儲かる売買システムを作る」 | 公開されている厳密な検証がすべてエッジ未確認。この前提で作ると高確率で失望する |
| ✅「Jev の判断力を自分のデータで測る装置を作り、戦略ごとにリアルタイムで判断を出す」 | **合理的。**コストがほぼゼロ、設計パターンは確立済み、検証の枠組みも先行事例から借用できる |

### 推奨構成

```
① 市場データ（yfinance + SQLite キャッシュ / 将来は証券会社 API）
② 特徴量計算（pandas。Jev には計算させない）
③ state 構築（point-in-time・匿名化。バックテストとライブで同一コード）★核心
④ Jev 判断（全戦略を 1 リクエスト。record/replay キャッシュで再現性を担保）
⑤ 判断 → サイズ変換（しきい値 3 段：自動 / レビュー / 何もしない）
⑥ ポートフォリオ（約定・手数料・スリッページ・ハードガード。全部コード）
⑦ 評価（PnL + Brier + キャリブレーション + ベースライン比較）★第一の成果物
```

### 運用コストの結論

- **Claude のトークンは運用時に一切使わない**（開発時のみ）
- Jev API は**日足リアルタイム運用で月 1 円**、日足 2 年バックテストで 26 円
- **PC 購入は不要**。損益分岐まで桁が 2 つ以上足りず、そもそも Jev は自己ホスト不可
